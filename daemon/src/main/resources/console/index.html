Loong 是什么

面向 AI 编程的显式结构语言，编译到 JVM。AI 直接编辑 AST 节点（不是文本）， 每次编辑自动触发增量编译；人类通过本页面监督、审批，不逐行读代码。

开始使用
1. 建个项目目录进去，敲 loong 就能用（无参数 = loong up，启动/复用本目录的 daemon）：
mkdir myproj && cd myproj
loong        # 前台启动 daemon（Ctrl+C 停止）；已在运行则显示地址直接复用
2. 把编程 agent 经 MCP 接入：command 填 <安装目录>/loong，args 填 ["mcp", "--project", "<项目目录>"]（「MCP」页有可复制的配置模板与连接状态）
3. agent 编辑节点 → 本页「AI 活动流」实时显示每次变更与诊断
4. agent 请求审批时，本页弹出「人工审批」对话框，批准或拒绝
5. 「代码」页签是 AST 渲染的只读文本视图（悬停可见节点 ID 与诊断）
6. 「测试」页签运行内联测试；「版本历史」由 agent 的 commit/diff/checkout 工具驱动
loong 命令详细用法 
loong                    启动/复用当前目录的 daemon（默认命令，等同 loong up）
loong up                 未运行则前台启动（Ctrl+C 停止）；已在运行则显示地址复用
loong stop               停止当前目录的 daemon
loong mcp                MCP stdio 桥（agent 接入用，由 agent 拉起，一般不手敲）
loong list               列出本机所有运行中的 Loong daemon（PID/端口/项目目录）
loong check <file>       编译检查；build <file> [-d <dir>]；run <file>；test <file>
loong help               完整帮助        loong --version  查看版本

项目目录：缺省 = 当前工作目录，--project <目录> 或环境变量 LOONG_PROJECT 覆盖；
产物就地落盘：workspace.db（AST 持久化）、loongd.json（端点）、registry/、cache/、daemon.log、
build/（构建 jar 与 class 中间产物，见「构建」页）。
每个项目一个常驻 daemon，端口随机分配互不冲突；Web UI 地址以启动输出为准（即本页）。

语言纪律由编译器强制：每个函数必须有 doc 注释与测试、 函数体超过 50 条语句拒绝编译、模块循环依赖拒绝编译——不靠 review 维持。

如何把编程 agent 接入 Loong

把 loong 配置为 agent 的 MCP server（args 首参 mcp，stdio JSON-RPC）。 桥启动时自动确保 daemon 在运行（未运行则拉起）——agent 先起、用户先起都成立； agent 断开后 daemon 常驻（loong stop 停止）；同一项目可挂多个 agent， 多项目互不冲突（loong list 查看本机全部）。
