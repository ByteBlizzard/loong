# ADR-0004 NodeId 分配规则

**状态**：Accepted（决策者批准，2026-10-29）
**关联**：design.md §4.1、§4.2；ast-schema-v1.md §3

## 决策

1. NodeId 为 **u64**；`0` 保留为 `NONE`（表示"无引用"），有效 ID 从 1 开始。
2. **分配域 = 工作区**（daemon 管辖的全部模块共用一个分配器）；分配器是唯一签发点（`engine/ast/IdAllocator`）。
3. **单调递增、永不复用、永不重排**：删除节点只移出节点表，其 ID 永久废弃。
4. **水位持久化**：分配器当前水位随节点表每次落盘一并写入；恢复时从 `max(已存最大 ID, 水位)` 之后继续，防止崩溃窗口内复用。
5. 序列化（ADR-0002）保持 ID 不变；**跨工作区合并时若发现 ID 冲突，显式报错拒绝**（不静默重映射）。跨工作区合并不在 v1 范围。

## 理由

稳定 ID 是「AI 编辑指令 = 修改节点 f3a2 而非改第 47 行」的基础（design §4.1）；任何复用都会让历史引用（诊断、测试结果、diff、MCP 会话）指向错误节点。

## 后果

- ID 单调性可作为增量判断的辅助信号（新节点 ID 必大于历史最大值）；
- 长期运行的工作区 ID 空间单调增长，u64 在任何实际尺度下不可耗尽。
