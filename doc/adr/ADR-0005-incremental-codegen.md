# ADR-0005 增量 codegen 设计（函数级字节码缓存）

**状态**：Accepted（2026-10-30 全量实施：拷贝路径、缓存接线、差分语义化、行为级运行验证均落地）

## 目标

编辑后只重新生成受影响的函数，编译时间随编辑规模而非模块规模增长（design §1.2「编译快」在代码生成段的兑现）。

## 技术：ClassReader 拷贝 + 规范序 + 语义差分

1. **缓存单元**：宿主类中的每个函数方法。`ModuleState` 记录 `函数节点 → 子树内容哈希`（`TestRunner.subtreeHash` 已具备该能力）与上次生成的类字节。
2. **拷贝机制**（ASM 标准做法）：新 `ClassWriter` 上用 `ClassReader.accept` 遍历旧宿主类，`visitMethod` 对**哈希未变**的方法返回新 writer 的 MethodVisitor（逐字节原样拷贝，含已算好的栈帧），对**已变/新增**的方法返回 null 跳过；随后把变更函数重新发射到同一 writer。
3. **字节兼容前提（本次已落地）**：全量发射按**方法名规范排序**。没有规范序，拷贝保留的旧方法顺序 + 追加的新方法顺序 ≠ 全量发射顺序，字节永不相等。
4. **差分门禁升级**：字节级比较升级为**语义级**——两侧类集分别经解析提取 `类 → 方法名 → 方法字节哈希` 的多重集比较，消除拷贝/发射顺序差异的噪声。asm-util（已在测试类路径）可承担提取。
5. **失效规则**：函数子树哈希变化 → 重发；跨模块绑定（Externals）、`<clinit>`（常量集）、main 桥、spawn 合成类随宿主整体重发（它们小，不缓存）。

## 已落地地基（本 ADR 的第一部分）

- 宿主类函数发射已改为按方法名排序（全量路径自身的字节确定性，与未来拷贝路径兼容）；
- 既有差分测试（增量 == 全量）继续以字节级比较守护当前正确性。

## 剩余工作（需专门周期）

- ModuleState 缓存字段 + CodeGenerator 的 previousClasses/previousHashes 接线；
- ClassReader 拷贝路径 + 变更集计算；
- 差分门禁语义化比较；
- 大模块基准测试（>500 函数）量化收益。

## 风险

- 拷贝方法的栈帧在新类常量池偏移下的重定位由 ASM 处理（成熟路径），但需差分+conformance 双门禁兜底；
- 方法名冲突（同名重载不存在于 Loong；impl 名 `Itf$Struct$fn` 全局唯一）——已验证无冲突源。
